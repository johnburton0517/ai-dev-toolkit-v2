### Review Workflow

**Step 1: Determine Review Scope**
Parse `--scope` from arguments. If not provided, **ask user** with 3 options:
1. Local changes — uncommitted + untracked
2. Branch changes — all commits vs base branch
3. Full codebase — everything

Wait for selection.

| Scope | What is reviewed |
| local | Uncommitted tracked + untracked files |
| branch | All commits on branch vs base |
| full | Entire codebase |

**File collection commands:**
- local: `git diff --name-only HEAD` + `git ls-files --others --exclude-standard`; diff via `git diff HEAD -- <file>`; read untracked directly
- branch: `git diff --name-only <base>...HEAD`; diff via `git diff <base>...HEAD -- <file>`
- full: `git ls-files`; read directly

Base branch resolution (branch scope):
1. `.cdk/settings.md` → `base_branch`
2. `git symbolic-ref refs/remotes/origin/HEAD ...`
3. Fallback: `main`

Store file list AND diff command. Pass both explicitly to every sub-agent.

**Step 2: Categorize Files and Run Reviews**
Categorize by risk (high: auth/data/APIs, medium: business logic, low: UI/docs/tests).
Spawn enabled agents in parallel.

**When spawning each agent, include:**
- Review scope name
- Exact file list
- Exact diff command per file

Agents must only review specified scope.

**Step 3: Categorize Findings**
Classify as Critical (must fix before PR), Warning (should fix), Info (nice to have).

### Finalization CHECKPOINT
Findings summary table: Critical/Warning/Info counts.

If action items exist, display table:
| Priority | Category | File/Area | Action |

Ask user to confirm which items to address.
