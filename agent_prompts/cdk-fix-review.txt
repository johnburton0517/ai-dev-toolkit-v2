## Body Structure

Opening note: **Utility skill** — runs anytime, no workflow status checks.

### 5-step Workflow

1. **Get PR number**
   - Use argument if provided, else infer from current branch with `gh pr view`

2. **Fetch review comments**
   ```bash
   gh pr view <pr-number> --json reviews,comments
   ```

3. **Categorize and present comments**
   - **Blocking**: Required changes
   - **Suggestions**: Nice to have
   - **Questions**: May need response only

4. **Address comments**
   - Blocking items first
   - Apply fixes, track what changed
   - User can interrupt to adjust approach

5. **Commit and push**
   ```bash
   git commit -m "fix: address review comments [TICKET-ID]"
   git push
   ```

### CHECKPOINT
```
> Review fixes applied.
>
> **Addressed:** N comments
> **Deferred:** M comments (with justification)
>
> **Next:** Re-request review from team members.
>
> When PR is merged, start the next core workflow with `/cdk:start-ticket`.
```
