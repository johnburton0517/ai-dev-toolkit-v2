You are creating the **ai-dev-toolkit** repository from scratch — a plugin marketplace that transforms source agent/skill primitives into installable plugins for Claude Code, GitHub Copilot, and Cursor.

## Your Task

Design and implement the complete repository: build tooling, config, marketplace manifests, documentation, quality gates, and at minimum one fully-featured plugin (the **CDK — Core Development Kit** plugin). The result must match the architecture and conventions described below.

Work in phases. For each phase, produce the files listed. Return file paths and complete file contents. Do not skip validation tooling or tests for the build pipeline.

---

## Project Purpose

**ai-dev-toolkit** is a single-repo marketplace for enterprise-governed AI coding assistant plugins.

- **Source of truth:** `src/plugins/<plugin-id>/` — agents, skills, MCP config authored as Mustache-templated markdown
- **Build output:** `plugins/claude/`, `plugins/copilot/`, `plugins/cursor/` — committed artifacts teams install directly
- **Marketplace manifests:** `.claude-plugin/`, `.github/plugin/`, `.cursor-plugin/` — point installers at built plugins
- **No separate registry** — the repo itself is the marketplace

### Core Architecture

```
src/plugins/<plugin-id>/          config/{claude,copilot,cursor}.yml
         │                                    │
         └──────────────┬─────────────────────┘
                        ▼
              scripts/build.js (Mustache render + transforms)
                        │
         ┌──────────────┼──────────────┐
         ▼              ▼              ▼
  plugins/claude/  plugins/copilot/  plugins/cursor/
         │              │              │
         ▼              ▼              ▼
  .claude-plugin/  .github/plugin/  .cursor-plugin/
  marketplace.json marketplace.json marketplace.json
```

### package.json requirements

- `"type": "module"` (ESM)
- Node >= 18
- Scripts: `build`, `lint`, `lint:js`, `lint:yaml`, `format`, `format:check`, `test`, `test:watch`, `test:coverage`, `prepare` (husky)
- DevDependencies: mustache, js-yaml, gray-matter, vitest, eslint, prettier, husky, lint-staged, commitlint, yaml-lint
- lint-staged: auto-format/lint scripts, config yml, plugin.yaml files

### Build orchestrator (scripts/build.js)

- Wipe `plugins/` directory on each build (clean slate)
- Discover plugins from `src/plugins/` via `loadPlugins()` — skip plugins with `publish: false`
- Support targets: `claude`, `copilot`, `cursor` (all by default, or single target via CLI arg)
- Load per-target config from `config/{target}.yml`
- Delegate to `buildClaude`, `buildCopilot`, `buildCursor`
- Generate marketplace.json manifests in `.claude-plugin/`, `.github/plugin/`, `.cursor-plugin/`

### Config files (config/*.yml)

Each ecosystem config must define:

| Key | Purpose |
| --- | ------- |
| `pluginsDir` | Output root (e.g. `plugins/claude`) |
| `marketplaceDir` | Manifest directory |
| `marketplace` | Name, version, owner, description |
| `HEADER` | Mustache template for `{{{HEADER}}}` token replacement |
| `tools` | Map of tool keys → ecosystem-specific invocation text |
| `hooks.events` | Common kebab-case → ecosystem-specific event names |
| `hooks.pluginRoot` / `pluginRootPattern` | Plugin root variable for hook scripts |
| `paths.configDir` | Ecosystem config dir (`.claude`, `.github`, `.cursor`) |

Tool keys available for `{{{tools.read_file}}}` etc.: `read_file`, `write_file`, `edit_file`, `run_command`, `search`, `search_files`

### Schema (config/schema.md)

Document the authoritative contract:

**plugin.yaml fields:** name, version, description, owner, risk (low|medium|high), compliance (array), tags, goals, publish (boolean, default true)

**Primitive frontmatter:** name, description, optional deprecated/supersededBy, ecosystem blocks (`claude:`, `copilot:`, `cursor:`)

**Mustache tokens:**
- `{{{HEADER}}}` — triple braces, unescaped
- `{{{tools.<key>}}}` — tool invocation text
- `{{#claude}}...{{/claude}}` — conditional sections

**Skills layout:** nested subdirectories per skill with `SKILL.md` entry point; optional `scripts/`, `references/`, `assets/`

**Hooks/MCP:** common source format in `hooks/hooks.json` and `mcp.json`, transformed per ecosystem

## Phase 2: Build Pipeline Implementation

Implement modular build with these responsibilities:

### plugins.js
- `loadConfig(root, target)` — parse YAML config
- `loadPlugins(pluginsDir)` — discover directories with plugin.yaml, filter by publish
- `findTemplates(dir)` — recursive .md discovery
- `findFiles(dir)` — recursive all-file discovery

### render.js
- Parse YAML frontmatter with gray-matter
- Render body through Mustache with context: frontmatter fields, tools map, ecosystem flags (claude/copilot/cursor booleans), paths
- Validate required frontmatter (name, description)

### validate.js
- Required fields present
- Valid semver in plugin.yaml
- Valid email for owner
- Known risk level
- At least one compliance tag
- No forbidden ecosystem-specific syntax leaking into wrong targets

### build-{claude,copilot,cursor}.js
Each builder must:
- Copy/render agents from `src/plugins/<id>/agents/*.md` to ecosystem-appropriate output paths and filenames
- Copy/render skills preserving directory structure under `skills/<skill-name>/SKILL.md`
- Copy non-markdown supporting files (scripts, templates, assets) unchanged
- Transform and emit MCP config (`.mcp.json` for Claude, `mcp.json` for Cursor, merged config for Copilot)
- Transform and emit hooks if present
- Copy settings-template.md, README.md if present
- Emit per-plugin manifest (plugin.json)

**Naming conventions:**
- Claude agents: `plugins/claude/<id>/agents/<frontmatter-name>.md`
- Copilot agents: `plugins/copilot/<id>/agents/<frontmatter-name>.agent.md`
- Cursor agents: `plugins/cursor/<id>/agents/<frontmatter-name>.md`
- Skills: preserve `skills/<skill-dir>/SKILL.md` structure in all targets

### transform-{claude,copilot,cursor}.js
- Map common hook events to ecosystem-specific names
- Replace `${PLUGIN_ROOT}` / plugin root patterns
- Strip or merge ecosystem-specific MCP overrides
- Apply Copilot defaults (type: local, tools: ["*"])

### Tests (tests/unit/build/)
Write Vitest unit tests for:
- Plugin discovery and publish filtering
- Mustache rendering (HEADER, tools, conditionals)
- Frontmatter validation
- Each build target (agent naming, skill structure, MCP transform)
- Hook event mapping

Exclude `plugins/` from test runs (vitest.config.js).

### CDK Workflow State Model

`.cdk/workflow-state.json` is a JSON **array**:

```json
[
  {
    "ticket_id": "123",
    "branch": "feat/123-short-slug",
    "stage": "started",
    "active": true
  }
]
```

Stages: `started` → `researched` → `planned` → `implemented`

Per-ticket artifacts in `.cdk/<ticket-id>/`:
- `research.md` — codebase findings (written by cdk-research)
- `plan.md` — implementation spec with YAML frontmatter (written by cdk-plan)
- `implementation-notes.md` — build summary (written by cdk-implement)

### CDK Skill Conventions

- All skills: `{{{HEADER}}}` after frontmatter
- Workflow skills: `<workflow_detection>` blocks, required stage gates, user approval CHECKPOINTs
- Utility skills: note "runs anytime, no workflow status checks" where applicable
- `<CHECKPOINT>` blocks for user-facing completion messages
- `{{#copilot}}...{{/copilot}}` for ecosystem-specific checks (e.g. cdk-onboard Check 6)

## Key Design Principles

1. **Write once, build many** — single source in `src/`, three ecosystem outputs
2. **Committed artifacts** — `plugins/` IS the marketplace; no separate distribution repo
3. **Governance at plugin level** — risk, compliance, owner in plugin.yaml; not duplicated in every primitive
4. **Agents are spawned, not invoked** — review/research/planning agents have `user-invocable: false`
5. **File-based workflow state** — CDK persists context in `.cdk/` without external databases
6. **Clean build** — `npm run build` wipes and regenerates all output
7. **Conventional commits** — enforced by hooks and mirrored in cdk-commit skill
